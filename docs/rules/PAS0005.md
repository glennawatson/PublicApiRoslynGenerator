# PAS0005 — Public API baseline could not be read

| Item | Value |
| --- | --- |
| Category | PublicApi |
| Severity | Error |
| Code fix | None |
| Default | Enabled |

The baseline contains invalid C# declaration syntax. A truncated declaration or missing delimiter
prevents the project's API from being compared with its recorded contract. PAS0005 reports the
syntax error; addition, removal and change checks are skipped until the baseline is repaired.

## When it fires

An available baseline contains a syntax error. The diagnostic includes the syntax-error message and
marks the offending position in the baseline, which may be just after the incomplete text.
Only the first syntax error is reported.

### Not reported

- A missing baseline file. PAS0004 covers a missing configured baseline when enabled.
- A baseline whose contents are unavailable. That case produces no PAS0005 diagnostic.
- An empty baseline. It is valid and can produce PAS0001 diagnostics for exposed declarations.
- Valid declaration text that differs from the source. PAS0001, PAS0002 and PAS0003 cover those
  differences.

## Examples

For source containing `Sample.Thing` with a public `int Value { get; set; }` property, a truncated
`PublicAPI/net10.0/PublicAPI.txt` reports an error at the incomplete accessor:

```csharp
namespace Sample;

public class Thing
{
    public int Value { get; set // PAS0005
```

The diagnostic message includes `{ or ; or => expected`. Repair the baseline so it matches the source:

```csharp
namespace Sample;

public class Thing
{
    public Thing() { }
    public int Value { get; set; }
}
```

If the baseline should be regenerated from the source, empty the existing file and apply
*Update the public API baseline* from a resulting PAS0001 diagnostic. Review the whole regenerated
file, since this accepts every difference for that target framework.

## Configuration

The default severity is `error`. The severity entry is:

```ini
dotnet_diagnostic.PAS0005.severity = error
```

For this baseline-file diagnostic, apply it project-wide in a `.globalconfig` with `is_global = true`,
or a project-level `.editorconfig` marked `is_global = true`, outside any file sections.

There are no options that relax the syntax requirement; the shared surface filters do not affect
whether baseline text is valid.

`EnablePublicApiBaseline`, `PublicApiBaselineDirectory`, `PublicApiBaselineFileName` and
`PublicApiBaselineFile` control baseline setup and placement; see
[Multi-targeting](../../README.md#multi-targeting).

Regeneration through a PAS0001 code fix requires a file named `PublicAPI.txt`. Repair a differently
named baseline directly. If regeneration needs custom surface options, put those options in a
project-level `.globalconfig` with `is_global = true`; the fix does not apply options from
`.editorconfig` sections.

## When to suppress

Suppress temporarily while repairing or replacing a known malformed baseline in a project whose API
comparison is deliberately deferred. Put this in that project's `.globalconfig`:

```ini
is_global = true
dotnet_diagnostic.PAS0005.severity = none
```

Suppression does not restore API checking: additions, removals and changes remain unchecked until
the baseline is valid. A pragma in the library's C# source cannot silence an error in the baseline.
