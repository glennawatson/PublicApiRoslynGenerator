# PAS0005 — Public API baseline could not be read

| Item | Value |
| --- | --- |
| Category | PublicApi |
| Severity | Error |
| Code fix | No |
| Default | Enabled |

## Cause

The baseline exists but is not valid C# declaration text, so it cannot be turned into a set of
declarations.

```text
// PublicAPI/net10.0/PublicAPI.txt — a hand-edit truncated the accessor list
public class Thing
{
    public int Value { get; set   // PAS0005: { or ; or => expected
```

## Rule description

The baseline format is ordinary C#, which is what lets the compiler read it back and what makes the
diff reviewable. The cost of that choice is that a hand-edit can leave the file unparseable.

Without this rule the file would look like an *empty* baseline, and every member in the assembly
would be reported as newly added — burying the one-line edit that actually caused it under hundreds
of [PAS0001](PAS0001.md) diagnostics. Reporting the parse failure instead keeps the build pointed at
the real cause, and the comparison is skipped entirely until the file reads again.

The diagnostic carries the parser's own message and is located where the parser gave up, which is
usually at or just after the damage.

## How to fix violations

Repair the file, or regenerate it: delete its contents, build, and apply the
*Update the public API baseline* code fix from any [PAS0001](PAS0001.md) diagnostic.

## Performance

Parsing is cached against the file's contents, so an unchanged baseline is read once however many
times the compilation runs.
