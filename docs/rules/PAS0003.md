# PAS0003 — Public API differs from the baseline

| Item | Value |
| --- | --- |
| Category | PublicApi |
| Severity | Error |
| Code fix | Yes — *Update the public API baseline* |
| Default | Enabled |

## Cause

A member still exists, but its declaration no longer matches the baseline.

```csharp
// baseline: public int Value { get; set; }
public long Value { get; set; } // PAS0003
```

## Rule description

The member's identity — container, kind, name, generic arity and parameter types — is unchanged, so
this is one member declared differently rather than one member replacing another. Reporting it that
way names the single member and shows both forms, instead of an unrelated-looking removal paired with
an addition.

A difference here is visible to consumers and can break them at compile time or at run time even
though the name and parameter types are untouched:

| change | what a consumer sees |
| --- | --- |
| return type | call sites that assign the result stop compiling |
| parameter default | recompiled callers bake in a different value |
| parameter name | named arguments stop compiling |
| nullability annotation | new warnings, or a null they were not expecting |
| `virtual`, `abstract`, `sealed`, `static` | overrides and call patterns stop compiling |
| an attribute | behaviour that depends on it changes |

## What this rule reports

Only a declaration whose identity matches a baseline entry but whose rendered text does not.
Formatting is never the cause: both sides are re-rendered from the same code, so indentation,
member order and attribute order cannot differ on their own.

## How to fix violations

Restore the declaration, or accept the change with the code fix, which rewrites the baseline for the
target framework being built.

## Performance

The rule runs as a symbol action, so the per-declaration cost is a dictionary lookup and a string
comparison.
