# PAS0001 — Public API is not in the baseline

| Item | Value |
| --- | --- |
| Category | PublicApi |
| Severity | Error |
| Code fix | Yes — *Update the public API baseline* |
| Default | Enabled |

A declaration is visible outside the assembly but absent from the baseline for the target framework
being built. Adding public API creates a contract that consumers can depend on; recording the addition
in the checked-in baseline makes that commitment reviewable.

## When it fires

Only projects with an available, syntactically valid baseline are checked for additions. An empty
baseline counts as valid and causes the exposed declarations to be reported.

- An externally visible type or member is missing from the baseline: types, constructors, methods,
  properties, indexers, fields, enum members, events and operators are covered.
- `protected` and `protected internal` declarations count when their containing types are externally
  visible, because consumers can reach them through inheritance. Explicit interface implementations
  on externally visible types are also part of the surface.
- An implicit parameterless constructor of a non-record class is missing from the baseline. Its
  diagnostic appears on the class declaration; other additions are marked on their own declarations.

### Not reported

- Internal or private declarations, or public members inside an internal type, except for explicit
  interface implementations described above.
- Synthesized record equality and deconstruction members, or separate property and event accessors.
- An extension block with no externally visible members.
- Declarations excluded by the generated-code or namespace settings described under Configuration.
- A declaration already present with a different signature detail; PAS0003 covers matching
  declarations that differ.
- Additions when the baseline is missing, unavailable or malformed. PAS0004 covers a missing
  configured baseline when enabled; PAS0005 covers malformed baseline text.

## Examples

With this baseline in `PublicAPI/net10.0/PublicAPI.txt`:

```csharp
namespace Sample;

public class Thing
{
    public Thing() { }
    public int Value { get; set; }
}
```

The source adds an unrecorded property:

```csharp
namespace Sample;

public class Thing
{
    public int Value { get; set; }
    public int Extra { get; set; } // PAS0001
}
```

To accept the addition, keep the source and update the baseline:

```csharp
namespace Sample;

public class Thing
{
    public Thing() { }
    public int Extra { get; set; }
    public int Value { get; set; }
}
```

With the default configuration, *Update the public API baseline* writes this corrected baseline.
It rewrites the whole file for the target framework being edited, accepting other additions,
changes and removals too. Review the entire diff. If the addition is unintended, remove it or reduce
its accessibility instead.

## Configuration

The default severity is `error`. Set it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PAS0001.severity = error
```

The shared `publicapisharp.include_assembly_attributes`, `publicapisharp.include_generated_code`,
`publicapisharp.excluded_attributes`, `publicapisharp.included_attributes` and
`publicapisharp.excluded_namespace_prefixes` settings control the surface checked for additions;
see [Configuration](../../README.md#configuration).
`EnablePublicApiBaseline`, `PublicApiBaselineDirectory`, `PublicApiBaselineFileName` and
`PublicApiBaselineFile` control baseline setup and placement; see
[Multi-targeting](../../README.md#multi-targeting).

The code fix updates files named `PublicAPI.txt`; edit a differently named baseline directly. For
custom surface options used with the code fix, put them in `.globalconfig` with `is_global = true`:
the fix does not apply options from `.editorconfig` sections.

## When to suppress

Suppress additions in a prototype or application project whose exposed declarations are deliberately
outside API compatibility review. In that project's `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PAS0001.severity = none
```

For a maintained library, accepting the baseline change keeps the new API tracked. If only generated
helpers or an unsupported namespace should be excluded, use the corresponding surface option instead.
