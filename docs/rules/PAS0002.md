# PAS0002 — Public API in the baseline no longer exists

| Item | Value |
| --- | --- |
| Category | PublicApi |
| Severity | Error |
| Code fix | No lightbulb — see below |
| Default | Enabled |

## Cause

The baseline records a member the assembly no longer exposes.

```text
// PublicAPI/net10.0/PublicAPI.txt
public class Thing
{
    public int Value { get; set; }
    public int Gone { get; set; } // PAS0002: nothing in the assembly declares this any more
}
```

## Rule description

Removing public API breaks every consumer that used it. The deletion has to be an explicit, reviewed
edit to the baseline rather than a silent side effect of a refactor — which is exactly what happens
when a member is renamed, has its accessibility reduced, or is moved to another type.

The diagnostic is reported on the baseline line, because there is no longer anything in the source to
point at, and that line is the text a reviewer has to agree to delete.

Reducing accessibility reads as a removal, which is correct: to a consumer outside the assembly,
`internal int Value` and no member at all are the same thing.

## What this rule reports

Only baseline entries with no matching declaration in the compilation. A member whose declaration
merely *differs* is reported by [PAS0003](PAS0003.md) instead, because its identity — container,
kind, name, generic arity and parameter types — still matches.

## How to fix violations

Restore the member, or accept the removal by regenerating the baseline.

There is no lightbulb on this diagnostic. Its location is a line in the baseline file, and an
additional file is not a document, so Roslyn never offers a code fix there. The removal is still
accepted by the same *Update the public API baseline* fix — regenerating the file drops the stale
entry — invoked from a [PAS0001](PAS0001.md) or [PAS0003](PAS0003.md) diagnostic that does sit in
source, or by regenerating from the command line:

```bash
dotnet format analyzers MyProject.csproj --diagnostics PAS0001 PAS0003 --severity info
```

On a multi-targeting project this writes one baseline per run, so repeat it until the build is clean.

## Performance

The rule runs once at compilation end, over the baseline entries that were parsed on first use.
