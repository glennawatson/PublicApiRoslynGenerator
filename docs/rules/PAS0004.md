# PAS0004 — No public API baseline for this target framework

| Item | Value |
| --- | --- |
| Category | PublicApi |
| Severity | Warning |
| Code fix | None |
| Default | **Disabled** (opt-in) |

A baseline path is configured for the target framework being built, but no baseline file is
available to the project. Without it, additions, removals and changes to that target's public API
are unchecked. This can leave a gap when a multi-targeting library adds another target framework.

## When it fires

PAS0004 must be enabled explicitly. It reports once for the project when a nonempty baseline path
is configured and no matching baseline is available among the project's additional files.

The message names the expected path and target framework. If the target framework is unavailable,
the message uses `(unknown)`; a configured path is still enough to report the missing baseline.
There is no source declaration or baseline line to mark.

### Not reported

- PAS0004 is left disabled, its default setting.
- No baseline path is configured. With the package's normal setup, this includes an outer
  multi-targeting build without a single target framework, or a project with
  `EnablePublicApiBaseline=false`.
- A baseline is available at the configured path, even if its filename is not `PublicAPI.txt`.
- A manually included additional file named `PublicAPI.txt` is available, even when no file matches
  the configured path.
- A baseline exists but is empty, malformed or has unavailable contents. Empty baselines can produce
  PAS0001; malformed text produces PAS0005.

## Examples

Suppose a `net10.0` project contains:

```csharp
namespace Sample;

public class Thing
{
    public int Value { get; set; }
}
```

With PAS0004 enabled and `PublicAPI/net10.0/PublicAPI.txt` configured but absent, the project
diagnostic is:

```text
There is no public API baseline at 'PublicAPI/net10.0/PublicAPI.txt' for target framework 'net10.0' // PAS0004
```

Create `PublicAPI/net10.0/PublicAPI.txt` with the matching declarations:

```csharp
namespace Sample;

public class Thing
{
    public Thing() { }
    public int Value { get; set; }
}
```

The source and baseline match, so the project has no baseline diagnostic. The package includes the
file automatically. Alternatively, create an empty file at that path and use
*Update the public API baseline* from a PAS0001 diagnostic to populate it. Create a separate baseline
for each target framework.

## Configuration

Enable PAS0004 with this severity entry:

```ini
dotnet_diagnostic.PAS0004.severity = warning
```

Because the diagnostic is project-wide, put the entry outside file sections in a project-level
`.globalconfig` with `is_global = true`, or a project-level `.editorconfig` marked `is_global = true`:

```ini
is_global = true
dotnet_diagnostic.PAS0004.severity = warning
```

Use `error` instead of `warning` if a missing baseline must fail the build.

`EnablePublicApiBaseline`, `PublicApiBaselineDirectory`, `PublicApiBaselineFileName` and
`PublicApiBaselineFile` control baseline setup and placement; see
[Multi-targeting](../../README.md#multi-targeting).

`TargetFramework`, supplied by the project/build, selects the target framework folder and identifies
the target in the diagnostic.

The settings read for this diagnostic are `build_property.PublicApiBaselineFile` (the resolved path;
absent or empty means no report) and `build_property.TargetFramework` (the target name; absent or
empty displays `(unknown)`).
Surface-filtering options do not affect whether a baseline is missing.

## When to suppress

Leave PAS0004 disabled in projects that have not adopted API baselines, such as application or test
projects that do not publish a library contract. If a shared configuration enables it, opt the
project out in its `.globalconfig`:

```ini
is_global = true
dotnet_diagnostic.PAS0004.severity = none
```

For a library that tracks its API, create the missing target framework's baseline instead of leaving
that target unchecked.
