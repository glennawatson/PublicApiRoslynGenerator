# PAS0004 — No public API baseline for this target framework

| Item | Value |
| --- | --- |
| Category | PublicApi |
| Severity | Warning |
| Code fix | No |
| Default | **Disabled** |

## Cause

The project resolved a baseline path, but no file exists there for the target framework being built.

## Rule description

Public API tracking only covers a target framework once a baseline exists for it. That makes silent
gaps possible in exactly the projects that need tracking most: a multi-targeting library adds
`net11.0`, no baseline is created for it, and that target's surface goes unchecked while every other
target is guarded.

The rule is disabled by default on purpose. Installing the package must not break a build before a
baseline has been adopted, so with no file present the analyzer does nothing at all. Enable this rule
when you want to be told which targets are untracked.

Nothing is reported when the project has not opted in at all — that is, when the package's MSBuild
targets did not resolve a path, which is the case for an outer multi-targeting build or a project
that sets `EnablePublicApiBaseline` to `false`.

## How to fix violations

Create the file the message names, then let the code fix fill it in:

```bash
mkdir -p src/MyProject/PublicAPI/net10.0
touch     src/MyProject/PublicAPI/net10.0/PublicAPI.txt
```

The next build reports every member as [PAS0001](PAS0001.md); applying the fix once writes the whole
surface into the new file.

To enable the rule:

```ini
dotnet_diagnostic.PAS0004.severity = warning
```

## Performance

The rule runs once at compilation end and only when no baseline file was found, so a tracked project
never pays for it.
